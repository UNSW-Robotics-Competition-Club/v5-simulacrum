# V5 SDK for C/C++

This SDK lets C and C++ user programs call VEXos through the SDK jump table at `0x037FC000`. The plain-C test programs in `programs/test-programs/` build against it. Types, docs and signatures come from vexide's [vex-sdk](https://github.com/vexide/vex-sdk) crates (MIT); a few slot names and prototypes were checked against VEXcode's SDK headers on a local install, which this repo doesn't include.

The files were generated by a script that isn't part of this repo, so don't edit them by hand without a reason.

| file | contents |
|---|---|
| `include/v5_sdk.h` | Types, enums, constants and 334 prototypes. Works as C99+ or C++, everything is `extern "C"`. |
| `src/v5_jumptable.S` | 520 ARM stubs, one per name: `movw/movt ip, slot; ldr pc, [ip]`. Each has its own section, so `--gc-sections` drops the unused ones. |
| `FUNCTIONS.md` | Reference list of every callable function (552 entries) by category, with slot, prototype and notes. Empty slots are flagged. |
| `src/v5_sdk.c` | Display wrappers that add `V5_DISPLAY_HEADER_HEIGHT` (32) to y, as both vex-sdk and libv5rt do. Also the printf-style functions (`vex_printf`, `vexDebug`, `vexDisplayPrintf`, …), which forward to the slot's `va_list` function, and `vexSystemVersion`/`vexStdlibVersion`. |

## Coverage (VEXos 1.1.5.0)

- 543 non-empty slots, of which 532 are named. The 11 unnamed ones are the 4 data words at 0x000–0x018 and 7 code slots: 0x7e8, 0x838, 0x83c, 0xba0, 0xf78, 0xf80 and 0xfac.
- 334 functions are declared with prototypes.
- 204 more get a stub but no declaration, because VEX publishes no prototype for them (the task, semaphore, event and timer APIs, for example). The header lists them in a comment; declare a prototype yourself before calling one.
- To call any slot raw: `((void (*)(int32_t, int32_t))V5_JT_SLOT(0x658))(x, y)`.

## Build

```sh
arm-none-eabi-gcc -mcpu=cortex-a9 -mfpu=neon-fp16 -mfloat-abi=softfp -ffunction-sections \
  -Isdk/include -c main.c sdk/src/v5_sdk.c sdk/src/v5_jumptable.S
```

- You must use the softfp float ABI. system_0 passes doubles in core registers (r2:r3), and the header refuses to compile with `-mfloat-abi=hard`.
- You still need your own startup code, linker script and program header (`vcodesig`, loaded at 0x03800000). This SDK only covers the OS calls.

## Differences from libv5rt

The stubs jump straight to the slot. In libv5rt, about 110 functions also check the VEXos version first and return 0 on older firmware. On 1.1.5.0 every check passes, so the stubs behave the same.

Two more libv5rt wrappers aren't copied:
- `vexControllerTextSet` waits until at least 50 ms have passed since its last call, because the controller drops text sent faster than that.
- `vexTaskGetArgs` emulates the call on VEXos ≤ 1.0.12.38.

Rate-limit controller text yourself.

## Caveats

- Some slots are empty in 1.1.5.0, so calling them jumps to 0 or 0xFFFFFFFF: `vexScratchMemoryPtr` (0x01c) and `vexSystemStdlibImpure{PtrAddr,DataAddr,DataSize}` (0xfa0–0xfa8).
- Only the signatures where vex-sdk and VEXcode disagreed were checked against the firmware's behaviour, not all of them.

## Test

```sh
wsl -d Ubuntu-24.04 -- bash scripts/sdk_test.sh      # from the repo root
```

`sdk_test.sh` compiles the header as C11 and C++17 with `-Werror -pedantic` (`test/sample.c`, `test/sample.cpp`). It checks that a hard-float build is rejected, links a sample at 0x03800000, and checks the stub encodings, including the VEX-only slots.
